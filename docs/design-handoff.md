# Whalica Personal Website — Codex 项目交接说明

> 状态：设计规格已确认，尚未开始正式网站实现。
> 交接日期：2026-10-20
> 项目目标：搭建个人展示与技术文章并重、可长期维护的个人技术网站。

## 1. 产品定位与约束

- 品牌：**Whalica**；展示性英文副标题可用 `Personal Website & Technical Journal`。
- 标语可选 `Build. Think. Iterate.`，中文定位为「记录算法思考、工程实践与持续探索」。
- 目标受众：算法竞赛选手、开发者、导师/专业访问者。
- 网站风格：**Minimal Professional / 极简专业型**；视觉克制、浅色优先、暗色适配，突出文字内容及真实作品。
- 中文为主、简短英文导航（Home / Blog / Projects / CP / About），暂不做完整多语言系统。
- 不做数据库、账号系统、管理后台、实时 CF Rating 大屏或花哨动画。
- 不杜撰用户个人资料、奖项、公开联系方式、项目状态、文章、项目技术栈或成绩；缺失处使用可替换的明确占位符。示意标题不得冒充已发表文章。
- 用户此前要求“暂不编写正式网站代码”。**这份文件是设计交接资料，不等于授权修改任何仓库。** Codex 接收后先检查工作区、明确实施范围，再按用户授权推进。

## 2. 技术选型建议

- 框架：Astro + TypeScript，尽量静态生成（SSG）。
- 主题：优先评估 AstroPaper 的当前版本、许可证、Astro 兼容性及实际维护状况；保留成熟文章功能，但首页及作品集需要高度定制；不应为了主题而妥协信息架构。
- 样式：Tailwind CSS（按所选主题实际技术方案决定），统一设计 Token。
- 内容：Astro Content Collections，文章 Markdown 优先，按需 MDX；项目以独立集合维护。
- 数学公式：KaTeX 或兼容的 remark/rehype 集成；代码：Shiki，按需 Expressive Code。
- 搜索：Pagefind；支持标签、归档、RSS、站点地图和基础 SEO。
- 部署：GitHub Pages + GitHub Actions；先遵循主仓、branch/path 和域名配置的实际情况，不预设所有者/仓库名。后续支持自定义域名。
- 不要无条件固定可能已过期的包版本；以实现时官方文档及包管理器验证为准。

## 3. 视觉规范

### 3.1 色板（亮色）

| Token | HEX | 用途 |
| --- | --- | --- |
| background | `#F8FAFC` | 全站背景 |
| surface | `#FFFFFF` | 卡片、文章 |
| subtle | `#F1F5F9` | 次级容器 |
| text-primary | `#172235` | 标题、正文 |
| text-secondary | `#475569` | 辅助信息 |
| accent | `#315AC5` | 链接、按钮、焦点 |
| accent-hover | `#24479F` | 悬停 |
| accent-soft | `#EBF0FF` | 轻微强调 |
| border | `#E2E8F0` | 分隔线、卡片描边 |

暗色对应：`#0F172A`（background）、`#172235`（surface）、`#E8EEF7`（text）；其余由可访问性对比度确定。

### 3.2 字体和尺寸

- 英文：Inter 或等效现代无衬线；中文系统字体优先；代码：JetBrains Mono / Cascadia Code 或等效等宽字体。
- 首页主标题：桌面 44–48px，移动 30–34px；文章标题：36–40px / 28–30px。
- H2：26px / 23px；H3：21px / 19px；正文：16px、行高约 1.8；辅助：13–14px；代码：13–14px。
- 全站内容最大宽 1120px，文章正文最大宽约 760px，桌面导航高约 68px。
- 间距：8px 基准（常用 8/16/24/32/48/64/96）；卡片圆角 12px；页面大区块间距 64–96px。
- 默认仅细描边，无明显投影；微弱 hover 状态；遵守 `prefers-reduced-motion`。
- 头像品牌：简洁 `W.` 字母标识；真实头像未提供时用明确占位图。

## 4. 页面路由与信息架构

| 路径 | 页面 | 主要内容 |
| --- | --- | --- |
| `/` | Home | Hero → Featured Projects → Selected Writing → CP 概览 → Footer |
| `/blog/` | Blog | 搜索、分类/标签、文章列表/归档 |
| `/blog/[slug]/` | Article | Markdown/MDX、公式、C++、目录、更新时间、相关文章 |
| `/projects/` | Projects | 项目卡片、类别/状态、真实截图 |
| `/projects/[slug]/` | Project Detail | 背景、本人角色、实际成果、设计决策、源码/文档 |
| `/cp/` | Competitive Programming | 竞赛经历、精选复盘、算法专题与训练方向 |
| `/about/` | About | 个人简介、教育背景、技术方向、联系方式（待补全） |
| `/search/`, `/tags/`, `/archives/` | 辅助页面 | 搜索与内容导航，不占主导航 |

### 首页内容原则

- 首屏先展示“Whalica / Software Engineering Undergraduate / 算法竞赛 + 开源软件开发”，而不是全部文章列表。
- Featured Projects：优先 OJ Insight 和 OJ Insight Coach，真实展示项目；Lica Studio 以开源组织/协作入口呈现，不冒充完成的软件产品。
- Selected Writing：精选约 3 篇，算法/竞赛/软件工程各具代表性；尚未发表时用占位或隐藏该区块，严禁虚构发布时间。
- CP 概览强调“观察、建模、验证、复盘”，而非堆积动态分数。
- 页脚包含 GitHub、RSS 等真实有效链接；未知 Email 不生成假地址。

### 博客分类

1. 算法与建模
2. 竞赛复盘
3. 软件工程
4. 学习与研究

细粒度标签示例：DP、Greedy、Data Structure、Modeling、XCPC、Open Source。

### 文章页特别要求

- 优先内容的阅读宽度与清晰的标题层级；桌面右侧文章目录，移动端折叠或内嵌。
- 公式与代码块只在容器内横向滚动，绝不出现整页横向溢出。
- 支持复制代码、代码高亮、文章更新时间、标签、SEO；可选阅读进度。
- 算法文章鼓励“原始观察 → 朴素算法 → 转移/瓶颈 → 结构发现 → 优化与证明 → 实现与复盘”，但不强制所有文章模板化。

### 项目详情页

- 项目真实名称、准确状态、本人职责、背景、技术架构、设计取舍、实际成果、界面截图、仓库/文档链接。
- 对 OJ Insight：重点是软件工程实践与长期演进，不与其产品站/文档站功能重复。
- Lica Studio 属于开放式开发者社区与组织入口，与个人站保持明确边界。

## 5. 初期内容与数据策略

- Posts 和 Projects 使用 Content Collections 分别管理。文章建议 frontmatter：`title`、`description`、`pubDate`、`updatedDate?`、`category`、`tags`、`featured`、`draft` 等。
- 项目建议 frontmatter：`title`、`summary`、`role`、`status`、`links`、`cover?`、`featured`；真实技术栈以仓库事实为准。
- 初始内容建议：About 1 页；OJ Insight、OJIC Coach 项目详情；Lica Studio 简介；经用户审阅的算法文章 2 篇、竞赛复盘 1 篇、工程文章 1 篇。
- 避免把 CF/ATC 解题数、Rating、GitHub Star 等作为首页稳定性的依赖。

## 6. 响应式与可访问性

- 手机 360–767px：单栏、导航折叠、卡片纵向堆叠、目录折叠。
- 平板 768–1023px：卡片视宽决定单双栏。
- 桌面 ≥1024px：完整导航、项目双栏、文章可带右侧目录。
- 浅/深色主题、键盘导航、可见焦点、语义标签、图片 alt、足够文本对比度（至少 WCAG AA）、减少动态效果支持。
- 避免默认加载巨大字体文件、自动播放媒体及重量级客户端框架。

## 7. 分阶段实施任务（供 Codex 确认授权后执行）

**阶段 A：环境与设计基线**
1. 了解当前工作目录、仓库状态、分支、已有框架、相关域名与用户约束；严禁覆盖已有文件。
2. 对照 Astro/AstroPaper 当前版本，确认合规、维护和依赖；记录选型理由及不兼容风险。
3. 建立 Design Tokens、导航与页脚、全站布局及基本无障碍交互。

**阶段 B：首页和文章页**
1. 先实现首页高保真布局，保持文字层级、空白、边框与统一强调色。
2. 建立 Posts Content Collection 和 Blog/Article 页面；验证一篇包含中文、公式、C++ 代码的示例文章，明确标注“演示”，不要当作真实博客文章公开。
3. 实现响应式及深色模式，检查 360px 宽度的整体溢出与横向滚动。

**阶段 C：完整信息架构**
1. Projects/Project Detail 页面与独立项目内容集合。
2. CP 与 About 页面，信息按事实填充，敏感或未知字段留空或占位。
3. 搜索、标签、归档、RSS、站点地图、SEO 与 GitHub Pages 自动部署。

**阶段 D：质量验收**
1. 安装依赖、lint/typecheck（如项目有对应脚本）、执行生产构建。
2. 验证桌面与手机页，确保所有实际导航可以点击，内部链接有效，公式和代码样式完整。
3. 检查浅/深色、静态资源路径、站点 base path、草稿不发布、RSS 输出及 404 页面。
4. README 记录启动、构建、内容发布、部署与更换域名的步骤。
5. 总结真实完成项、尚未完成项与未解决风险；不得声称未执行过的构建测试通过。
