## 3.1 三个基本问题

| 问题 | 要解决的事 | 答题时的落点 |
| --- | --- | --- |
| 封装成帧 | 在数据两边加首尾字段，让接收端能辨认帧的边界 | 帧首尾与数据是不同字段，长度按题意统计 |
| 透明传输 | 数据中碰巧出现和边界相同的模式时，仍能原样恢复 | 发送端填充，接收端按规则去填充 |
| 差错检测 | 判断接收到的帧是否出现可检出的差错 | CRC把余数作为帧检验序列加入帧中 |

**链路**是相邻节点间的物理通路，**数据链路**还包含为在该链路上传送数据所需的协议及实现。CRC检出错误后可以丢帧。需要可靠传输时，还要由相应协议处理丢失、重复和失序等问题。题目问“未检出差错”时，零余数代表通过该次校验。

### 例题 1｜期中第4题变式：把 CRC 的异或过程写全

数据 `1101011`，生成多项式 `G(x)=x³+x+1`，比特串 `1011`。求 FCS、发送序列和末位翻转后的余数。

**第一步，确定补零位数。** 多项式最高次为 3，除数有 4 位，余数用 3 bit 表示。把 3 个 0 接到数据右侧得 `1101011000`。

**第二步，从剩余最高位的 1 对齐除数，每次执行异或。** 模2减法与异或相同，逐位计算，无借位。下面每行都是对上一行完成一次异或后的值。

```text
1101011000  初始
0110011000  ⊕ 1011000000
0011111000  ⊕ 0101100000
0001001000  ⊕ 0010110000
0000010000  ⊕ 0001011000
0000000110  ⊕ 0000010110
```

**第三步，取定宽余数。** FCS 为 `110`。用它替换先前补上的三个 0，实际发 `1101011110`。正常接收时，对整个收到的序列除以 `1011` 得余数 `000`，接收端此时不再补 0。

**第四步，判断末位翻转。** 接收到 `1101011111`。末位翻转等于在原码字上异或错误项 `0000000001`。原码字可整除，模2运算下新余数就是错误项的余数 `001`，因此可以检出。

从算法角度看，CRC 的长除法是一个按最高位对齐、不断异或的过程。它和跨校数据汇总时做的文件哈希核对都在检查比特变化，但检查的范围与使用场景各自不同。Ethernet FCS只检查该链路的帧，文件摘要可以用于核对整个题目压缩包。

## 3.2 点对点协议 PPP

PPP帧常画为 `Flag / Address / Control / Protocol / Information / FCS / Flag`。标志字段为 `0x7E`，协议字段说明承载的协议。LCP负责建立与配置链路，NCP配置对应的网络层协议，链路建立过程中可以按协商进行鉴别。以下例题按题设处理信息字段，异步实际转义范围还和控制字符映射的配置有关。 [PPP 成帧规范 RFC 1662](https://www.rfc-editor.org/rfc/rfc1662.html)

### 例题 2｜期中第5题变式：异步与同步分别怎么填

**异步，按字节。** 原序列 `41 7E 7D 11 20`，题设要求转义 `7E`、`7D` 和小于 `20` 的字节。转义时先放 `7D`，然后发送原字节异或 `20` 的结果。

| 原字节 | 发送结果 | 按规则解释 |
| --- | --- | --- |
| `41` | `41` | 保持 |
| `7E` | `7D 5E` | `7E XOR 20 = 5E` |
| `7D` | `7D 5D` | `7D XOR 20 = 5D` |
| `11` | `7D 31` | 低于 `20`，按题设转义 |
| `20` | `20` | 等于阈值，按题设保持 |

结果是 `41 7D 5E 7D 5D 7D 31 20`，由 5 B 变成 8 B，增加 3 B。

**同步，按比特。** 原串 `011111110111110` 可拆成 `0｜1111111｜0｜11111｜0`。第一段连续七个 1 在第 5 个后插一个 0，得到 `11111[0]11`。第二段五个 1 同样在其后插 0，然后保留原本的末尾 0。结果是 `01111101101111100`，增加 2 bit。计数被原有的 0 或填充的 0 重置。

## 期中补充 停止等待的时间账

教材第5.4.1节给出停止等待的工作原理。期中第6题把这个模型放到点对点链路中计算。发送方发一帧后等确认，确认或数据丢失时可超时重传。用序号区分新帧和重复帧。效率题通常先按无误码模型，画出数据和 ACK 的最后一位分别到达的时刻。

### 例题 3｜期中第6题变式：利用率和有效吞吐量

数据帧 1200 B，其中有效数据 1100 B。ACK 为 50 B，两方向 4 Mbit/s，单向传播 3 ms，收到完整数据帧立即发 ACK，忽略处理与丢包。

```text
数据发送          1200 × 8 / (4 × 10^6) = 2.4 ms
数据最后一位到达  2.4 + 3 = 5.4 ms
ACK 发送         50 × 8 / (4 × 10^6) = 0.1 ms
ACK 最后一位返回  5.4 + 0.1 + 3 = 8.5 ms
数据发送时间占比  2.4 / 8.5 ≈ 28.24%
载荷有效吞吐量    1100 × 8 / 0.0085 ≈ 1035.3 kbit/s
```

占比的分子使用整帧的发送时间，有效吞吐量的分子使用载荷。比赛汇总脚本若自行设计为每个小块都等待应用确认，也会形成类似的空等。真实 TCP 使用窗口，应用确认与 TCP ACK 的计时口径仍需区分。

## 3.3 传统以太网、CSMA/CD 和 MAC 帧

共享式半双工以太网里，多个站争用同一传输媒体。CSMA/CD的顺序为先侦听、空闲时发送、发送期间检测碰撞、发生碰撞后停止并退避。最不利情况中，远端在本端信号到达前刚开始发，碰撞信号还要再传播回来，故争用期要考虑**往返传播时延**。集线器转发物理信号，多个端口共享碰撞域。现代会场的全双工交换链路可同时收发，通常按全双工以太网分析。

以太网MAC地址为 48 bit。无 VLAN 标签的常见以太网 MAC 帧包括目的和源地址、类型或长度、数据和 FCS。最小长度 64 B，常见最大长度 1518 B，均从 MAC 帧本身计，独立的前导和帧间间隔按题设处理。以太网上承载 IPv4 时常见 MTU 1500 B，指可承载的 IP 数据报大小。 [IPv4 over Ethernet，RFC 894](https://www.rfc-editor.org/info/rfc894/)

### 例题 4｜期中第7题变式：理论最短帧与退避时隙

100 Mbit/s 共享半双工，最远 300 m，信号速度 `2×10⁸ m/s`。先只计传播，之后按 512 bit 时间为退避时隙。求理论帧长、64 B实帧的发送时间，以及第四次碰撞后 `r=6` 的等待时间。

1. 单程 `τ=300/(2×10⁸)=1.5 μs`。最迟反馈要等 `2τ=3 μs`。发送时间应覆盖这段，因此理论最短 `100×10⁶×3×10⁻⁶=300 bit`。等于 37.5 B，若需要完整字节，至少向上取整为 38 B。
2. 64 B 实帧为 512 bit，在该速率下发完要 `5.12 μs`，覆盖题设的 `3 μs`。标准帧长度和本题纯传播推导各自有明确前提。
3. 第四次碰撞按截断二进制指数退避，`k=min(4,10)=4`，从 `0…15` 中取随机整数。`r=6` 对应 `6×512/(100×10⁶)=30.72 μs`。退避时隙按题设使用 512 bit 时间。

教材第3.3.4节把 `a=τ/T₀` 作为传播时间和发送时间之比，其中 `T₀=L/R`。在课件的理想上界模型里，一帧从开始发送到最后一位抵达最远站点，要占用 `T₀+τ`。于是极限利用率为 `T₀/(T₀+τ)=1/(1+a)`。实际还可能发生碰撞。再对照课件的10 Mbit/s实例，512 bit时间为51.2 μs。题目的速率变成100 Mbit/s时，用512重新除以给定速率。

## 3.4 交换机自学习与VLAN

交换机收到帧先用**源 MAC**更新地址表，再查**目的 MAC**决定往哪发。未知单播和广播在所属 VLAN 内向除入端口外的相关端口泛洪。已知单播走查到的出端口。目标已知且正好在入端口时，过滤该帧。站点换口后可用新的源帧更新地址表，长时间没有刷新会老化。写模拟题时，可以把地址表想成 `(VLAN, MAC) → port` 的映射。

### 例题 5｜期中第8题变式：泛洪、转发和过滤

端口1接A，端口2接B，端口3接一个包含C和D的外接网段，端口4接一台保持连接、本题中没有主动发送的主机。四个端口都处于同一VLAN的转发状态。各帧长度120 B，初始地址表为空，依次处理下表中的帧。求输出集合和总字节数。

| 到达帧 | 入端口 | 更新源项 | 查目的后的动作 | 输出集合 |
| --- | --- | --- | --- | --- |
| A→C | 1 | A→1 | C未知，泛洪 | {2,3,4} |
| C→A | 3 | C→3 | A已知，单播 | {1} |
| D→C | 3 | D→3 | C已知，同口过滤 | {} |
| B→D | 2 | B→2 | D已知，单播 | {3} |
| C→B | 3 | C→3 | B已知，单播 | {2} |

最终映射为 A→1、B→2、C→3、D→3。**按输出端口副本计数**，`3+1+0+1+1=6` 份，`6×120=720 B`。第三帧即使被过滤，源D也已经学到，第四帧才能直接发到3口。

### 联赛现场的VLAN

可把选手区、运维区和来访网络放在不同 VLAN。接终端的 Access 口通常让对应 VLAN 的流量以无标签形式交付，交换机互联的 Trunk 可承载多个 VLAN，常用 802.1Q 标签。需要跨 VLAN 通信时，在具备三层能力的设备上按策略配置网关。检查同 VLAN 跨交换机不通的问题时，沿接入口、两端上联 VLAN 放行、MAC学习端口逐段查，再做同 VLAN Ping。比较跨 VLAN 的情况时，还要查第4章的 IP 和网关。

- 传统中继器与集线器在物理层扩展信号。交换机在链路层按帧转发，分开各端口的碰撞域。
- VLAN 划分广播域。在同 VLAN 的多交换机网络里，广播仍可沿放行该 VLAN 的上联传递。
- 第3.5节的高速以太网复习接口速率、介质和双工方式。升级链路速率会缩短发送时延，传播仍取决于距离与介质。

## 自测与详解

1. **再做一遍CRC。** 数据 `10011101`，除数 `1011`。补零后 `10011101000`，逐次异或得 `00101101000 → 00000001000 → 00000000011`。FCS `011`，发送 `10011101011`。最后一位翻转时余数 `001`。
2. **再算一个确认周期。** 900 B帧含850 B载荷，ACK 25 B，两向2 Mbit/s，单程4 ms。数据发送3.6 ms，ACK发送0.1 ms，两个传播合计8 ms，因此周期11.7 ms。时间占比 `3.6/11.7≈30.77%`，载荷吞吐量 `850×8/0.0117≈581.2 kbit/s`。
3. **把同口过滤搬进机房。** 若交换机刚学到目标MAC在当前入端口，会先刷新帧的源MAC，再过滤该帧。若目的未知，则只在该帧所属VLAN内向其他转发端口泛洪。
