## 二、逐题解析

### 第1题　“年龄 ≤ 19 的年龄及姓名” ✅

**题干**：学生表 Student(S#, Sname, Ssex, Sage, D#, Sclass)，检索“所有年龄小于等于 19 岁的学生的年龄及姓名”。
**选项**：
A. **Select Sage, Sname From Student Where Sage <= 19;**
B. Select Sname From Student Where Sage <= 19;
C. Select * From Student Where Sage <= 19;
D. Select Sage, Sname From Student;
**标准答案：A**

- **A ✅** 要输出的列是**年龄 Sage 和姓名 Sname**（SELECT 子句），条件是 **Sage <= 19**（WHERE 子句）。列清单与条件都齐全，且**列的次序与题目一致（年龄在前）**。
- **B ❌** **漏了 Sage 列**，只投影出姓名，不满足“年龄及姓名”。
- **C ❌** `SELECT *` 输出**全部 6 列**（学号、姓名、性别、年龄、系别、班级），多出了 4 列，不符“年龄及姓名”。这是“多投影”的典型错误——**投影要求不多不少**。
- **D ❌** **漏了 WHERE 条件**，检索的是全体学生，不是“≤19 岁”。

**知识点**：§3.4.1 查询语句的一般格式；**SELECT 子句 = 投影（π），WHERE 子句 = 选择（σ）**，正好对应作业2 第7、17、25 题。

### 第2题　哪一行能插入 SC ✅

**题干**：`CREATE TABLE SC (S# CHAR(6) NOT NULL, C# CHAR(3) NOT NULL, SCORE INTEGER, NOTE CHAR(20));`
**选项**：
A. **('200823','101',NULL,NULL)**
B. ('201009','101',NULL,必修)
C. (NULL,'103',80,'选修')
D. ('201132',NULL,86,'')
**标准答案：A**

- **A ✅** S#='200823'（**非空**，6 字符，符合 CHAR(6)）、C#='101'（**非空**，3 字符）、SCORE 为 NULL（**该列允许空**）、NOTE 为 NULL（**允许空**）。四个值全部合法，**可以插入**。
- **B ❌** 第 4 个值 `必修` **没有加引号**。字符串常量必须用单引号括起来，`必修` 会被当成列名/标识符，**语法错误**。
- **C ❌** S# 取 NULL，**违反 `S# NOT NULL`** 约束（若 S# 是主码则还违反实体完整性）。插入失败。
- **D ❌** C# 取 NULL，**违反 `C# NOT NULL`** 约束。插入失败。

**知识点**：§3.5.1 INSERT 语句、§3.3 列级完整性约束（NOT NULL）、§3.6 空值。
**易错点**：① 空值 NULL **只有在该列未声明 NOT NULL 时才允许**；② 插入时字符串/日期必须加单引号，数字不加。

### 第3题　“张某某”的通配符个数 ⚠️ 本卷唯一真正的知识性错误

**题干**：检索“名字为张某某的所有同学姓名”（张某某 = **3 个汉字**）。
**选项**：
A. `Where Sname Like ‘张____’`（张 + **4 个下划线** = 共 5 个字符）
B. `Where Sname Like ‘张%’`
C. `Where Sname Like ‘张_’`（张 + **1 个下划线** = 共 2 个字符）
D. `Where Sname Not Like ‘张_ _’`
**标准答案：B**

**先数清楚通配符**（这是本题唯一的门槛）：

| 选项 | 写法 | 匹配的字符数 | 能否匹配“张某某”（3 字） |
|---|---|---|---|
| A | `张____` | **5** 个字符 | ❌ 不能（要求 5 个汉字） |
| B | `张%` | 张 + **任意个（含 0 个）** | ✅ 能（属于**超集**） |
| C | `张_` | **2** 个字符 | ❌ 不能（只匹配“张三”） |
| D | `NOT LIKE 张_ _` | 排除 2 字符的“张×” | ❌ 方向相反 |

- **A ❌** 4 个下划线要求“张”后**恰好还有 4 个字符**，即总共 5 个汉字（如“张一二三四”），“张某某”只有 3 个字，**匹配不上**。**若写成 `张__`（2 个下划线）才是精确答案**，但选项里没有这个写法。
- **B ✅** `%` 代表**任意长度（0 个或多个）的字符串**，`张%` 能匹配“张”“张三”“张某某”“张三四五”……**必然包含“张某某”**。题目问“哪一个结果**可以**被检索出来”，只要求**能检索到**，不要求“只检索到”，因此 B 成立。
- **C ❌** `_` 只匹配**单个字符**，`张_` 只能匹配 2 字姓名（张三、张伟），检索不到 3 字的“张某某”。
- **D ❌** `NOT LIKE` 是**取反**，检索的是“不姓张”或“不是 2 字”的人，与题意相反。

> ⚠️ **结论与教训**：**考试中先数清下划线的个数**，再判断。本题正确写法应是 `LIKE '张__'`（**2 个下划线**）；选项给的是 4 个，所以只能退而求其次选 `%`。
> 另需注意：`%` 与 `_` 是 SQL 的**通配符**，`%` = 任意多个字符，`_` = 任意**一个**字符，二者都**只能用在 LIKE 中**，不能用于 `=`。

**知识点**：§3.4.1 字符匹配（LIKE、%、_、ESCAPE）。

### 第4题　关于排序、唯一性、模糊查询的错误说法 ✅

**题干**：关于结果唯一性、结果排序、模糊查询，说法**不正确**的是（ ）。
**选项**：
A. **结果排序是在 Select 语句中通过增加 order by 子句实现的，后只能跟 DESC 或省略为降序。**
B. 在 Table 中要求无重复元组是通过定义 Primary key 或 Unique 来保证的；而在检索结果中要求无重复元组，是通过在 SELECT 子句中引入 DISTINCT 保留字来实现的。
C. 模糊查询是通过在 Select 语句的 Where 子句中引入运算符 like 来实现的。
D. 在 SELECT 语句的 Like 条件中，用“\%”去匹配字符 %，用 \_ 去匹配字符 _。
**标准答案：A**

- **A ❌（即答案）** 错误的点有两处：① `ORDER BY` 后面可以写 **ASC（升序）** 或 **DESC（降序）**；② **省略时默认是 ASC（升序）**，**不是降序**。所以“只能跟 DESC 或省略为降序”整句都站不住。
- **B ✅（正确）** 表内去重靠**主码/唯一约束**（`PRIMARY KEY`、`UNIQUE`）；**结果集**去重靠 `SELECT DISTINCT`。这是“存储层约束”与“查询层去重”的正确区分。
- **C ✅（正确）** 模糊查询 = `WHERE 列 LIKE '模式'`，运算符是 `LIKE`，还可用 `NOT LIKE`。
- **D ✅（正确）** 当要匹配的字符串本身含 `%` 或 `_` 时，用**转义字符**（`\`）转义：`\%` 匹配 `%`、`\_` 匹配 `_`；标准写法还要配 `ESCAPE '\'`，教材采用 `\` 作为默认转义符的约定。

**知识点**：§3.4.1（ORDER BY、LIKE、DISTINCT）。
**延伸记忆**：`ORDER BY 列 [ASC|DESC]`，**默认为 ASC**；多列排序时写 `ORDER BY 列1 DESC, 列2 ASC`，各列可分别指定方向。

### 第5题　去重命令 ✅

**题干**：下列（ ）命令用于去掉重复行。
**选项**：A. ORDER　B. DESC　C. GROUP　D. **DISTINCT**
**标准答案：D**

- **A ❌** `ORDER BY` 是**排序**，不去重。
- **B ❌** `DESC` 是 `ORDER BY` 的**降序**选项，也不是独立命令。
- **C ❌** `GROUP BY` 是**分组**，它虽然能把相同值“聚”到一起，但**结果仍是每组一行**，不是“去重”运算；用 `GROUP BY` 去重属于间接手法。
- **D ✅** `SELECT DISTINCT 列…` 才是 SQL 的**去重保留字**，它作用于**整个结果行**（多列时是“组合值”去重）。

**知识点**：§3.4.1；也与作业2 第10、20、21 题呼应：**关系是集合、元组不重复**，SQL 用 `DISTINCT` 把“物理上可能重复的结果”还原成严格集合。

### 第6题　HAVING 筛选什么 ✅

**题干**：在 SQL 语句中，HAVING 条件表达式用来筛选满足条件的（ ）。
**选项**：A. 行　B. 列　C. **分组**　D. 表
**标准答案：C**

- **A ❌** 筛选**行**是 `WHERE`（在分组**前**对元组过滤）。
- **B ❌** 筛选**列**是 SELECT 子句的投影。
- **C ✅** `HAVING` 作用于 **`GROUP BY` 之后**，对**每个分组**做筛选（如 `HAVING COUNT(*) > 3`、`HAVING AVG(Grade) >= 90`）。**HAVING 中可以使用聚集函数，WHERE 中不可以**。
- **D ❌** 没有“筛选表”这种说法（选表是 FROM 的事）。

**知识点**：§3.4.4 分组查询。**执行顺序**：`FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`，所以 WHERE 里不能写聚集函数，HAVING 里可以。

### 第7题　查询结果是什么 ✅

**题干**：在 SQL 语句中，一次查询的结果是一个（ ）。
**选项**：A. 记录　B. **表**　C. 分组　D. 数据项
**标准答案：B**

- **A ❌** “记录”只是一行，而查询结果通常是**多行多列**。
- **B ✅** SQL 的查询结果**仍是一个关系（表）**——这是 SQL 的“**封闭性**”，也是它能把查询结果当作表再参与运算（子查询、视图、`INSERT INTO … SELECT`）的根本原因。
- **C ❌** 分组是 `GROUP BY` 的中间产物。
- **D ❌** 数据项只是单个分量（一个单元格）。

**知识点**：§3.1 概述、§3.4。**“结果仍是表”是 SQL 的灵魂**：视图是虚表、子查询是临时表、`UNION` 的结果也是表。

### 第8题　A 字段不为空 ✅

**题干**：找出 A 字段上不为空的记录。
**选项**：A. A!=NULL　B. A<>NULL　C. **A IS NOT NULL**　D. A NOT IS NUL
**标准答案：C**

- **A ❌** 空值**不能**用 `!=` 比较。`A != NULL` 的运算结果是 **UNKNOWN**，不返回任何行。
- **B ❌** 同理，`A <> NULL` 也恒为 UNKNOWN。
- **C ✅** 空值判断**必须**用专门的谓词：`IS NULL` / `IS NOT NULL`。
- **D ❌** 语法错误：`IS NOT NULL` 不能写作 `NOT IS NUL`（且拼写漏了 L）。

**知识点**：§3.6 空值处理、§3.4.1 谓词 `IS [NOT] NULL`。这题与第29题同考点（作业1 第8、29 题也重复考过）。

### 第9题　查“Computer”课的男生姓名 ✅

**题干**：S(S#, SNAME, SEX)、C(C#, CNAME)、SC(S#, C#, GRADE)，查选修“Computer”课的男生姓名。
**选项**：A. **S, C, SC**　B. S　C. S, SC　D. SC
**标准答案：A**

拆解需要的信息落在哪个表：

| 题目要求 | 需要的列 | 在哪个表 |
|---|---|---|
| 男生 | SEX | **S** |
| 姓名 | SNAME | **S** |
| 课程 = Computer | CNAME | **C** |
| 是否选修（选课事实） | S#、C# | **SC** |

- **A ✅** 三张表都要：SC 提供“谁选了哪门课”、C 提供“哪门课叫 Computer”、S 提供“性别与姓名”。连接链：`SC.C# = C.C#`，`SC.S# = S.S#`。
- **B ❌** 只有 S，**无法知道谁选了 Computer**。
- **C ❌** 缺 C，**无法知道课程号对应的是不是 Computer**（除非预先硬编码了课程号，那不是通用答案）。
- **D ❌** 缺 S，**拿不到姓名和性别**。

**知识点**：§3.4.3 连接查询、§3.4.5 嵌套查询。
**参考写法**：
```sql
SELECT S.SNAME
FROM   S, SC, C
WHERE  S.S# = SC.S# AND SC.C# = C.C# AND C.CNAME = 'Computer' AND S.SEX = '男';
```

### 第10题　删除一个表的命令 ✅

**题干**：SQL 语言中，删除一个表的命令是（ ）。
**选项**：A. REMOVE　B. DELETE　C. CLEAR　D. **DROP**
**标准答案：D**

- **A ❌** `REMOVE` 不是 SQL 语句。
- **B ❌** `DELETE` 删除的是**表内的行**（`DELETE FROM 表 [WHERE…]`），**表和结构仍然存在**。这是本题最大的干扰项。
- **C ❌** `CLEAR` 不是 SQL 语句（`TRUNCATE TABLE` 才是清空行）。
- **D ✅** `DROP TABLE 表名` 删除**表结构＋数据＋索引＋视图依赖**，整张表消失。

**知识点**：§3.3.3 数据字典、§3.3.2 删表。**对比记忆**：

| 想做什么 | 语句 |
|---|---|
| 删表中**部分/全部行**，表还在 | `DELETE FROM S WHERE …` |
| 清空表全部行（不可回滚、快） | `TRUNCATE TABLE S` |
| **删除整张表**（结构+数据） | `DROP TABLE S` |
| 删除某列 | `ALTER TABLE S DROP COLUMN 列名` |

### 第11题　删除属性“年龄” ✅

**题干**：在表 S 中删除一个属性“年龄”，选用的 SQL 语句是（ ）。
**选项**：A. **ALTER TABLE S DROP Sage**　B. DELETE Sage from　C. UPDATE S Sage　D. ALTER TABLE S ‘Sage’
**标准答案：A**

- **A ✅** 删除列的**标准语句**：`ALTER TABLE 表名 DROP [COLUMN] 列名`（`COLUMN` 关键字在多数 DBMS 中可省略）。`Sage` 是列名，直接跟在 `DROP` 后即可（**不加引号**）。
- **B ❌** `DELETE` 只删**行**，不能删列；且“DELETE Sage from”语法不通。
- **C ❌** `UPDATE` 改的是**行的列值**，不是表结构。
- **D ❌** 列名不能加引号（`'Sage'` 是字符串常量，不是标识符），缺 `DROP` 关键字，语法错误。

**知识点**：§3.3.2 修改基本表。
**标准写法**：`ALTER TABLE S DROP COLUMN Sage CASCADE;`（`RESTRICT` 表示若被其他对象引用则拒绝删除，`CASCADE` 表示级联删除相关对象。）

### 第12题　“撤销已经存在的表 S” ⚠️ 平台答案错误

**题干**：若要**撤销**数据库中已经存在的表 S，可用（ ）。
**选项**：A. **DROP TABLE**　B. DELETE TABLE S　C. DELETE S　D. DROP S
**标准答案：A**（⚠️ 平台判分为 **B**）

- **A ✅** “撤销/删除整张表”的标准命令是 **`DROP TABLE S;`**。选项 A 给出的是“`DROP TABLE`”这一**命令模式**（完整写法加表名即 `DROP TABLE S`；还可写 `DROP TABLE IF EXISTS S CASCADE`）。
- **B ❌（平台判为正确，实为错误）** **`DELETE TABLE S` 在标准 SQL 中根本不存在**，任何 DBMS 都会报语法错误。`DELETE` 只能写 `DELETE FROM 表名 [WHERE…]`。
- **C ❌** `DELETE S` 缺 `FROM`，且删除的是行，不是表。
- **D ❌** `DROP S` 缺 `TABLE`，不是合法 SQL。

> ⚠️ **平台判分与标准冲突（本题丢 2.8 分）**
> - **标准答案：A（DROP TABLE）**——教材 §3.3.2 原文即“删除基本表：`DROP TABLE <表名> [RESTRICT|CASCADE];`”。
> - **平台答案：B（DELETE TABLE S）**——该语句是**语法错误的杜撰项**，属题库错误。
> - **建议**：若可申诉，引用 §3.3.2 原文；若只能按平台，填 B 但**心里按 A 记**，否则考试中真写 `DELETE TABLE` 会直接判错。

### 第13题　`LIKE '_A%'` 能检索出什么 ✅

**题干**：WHERE 条件中出现 `LIKE '_A%'`，下面哪个结果**可以**被检索出来？
**选项**：A. **BA**　B. AILI　C. CCA　D. 以上所有都可以
**标准答案：A**

模式拆解：`_`（第 1 个字符任意）＋ `A`（第 2 个字符必须是 A）＋ `%`（后面任意）。

| 候选 | 第 1 字符 | 第 2 字符 | 是否匹配 |
|---|---|---|---|
| A. **BA** | B（`_` 吃掉） | **A** ✅ | **匹配**（`%` 匹配 0 个字符） |
| B. AILI | A | **I** ❌ | 不匹配 |
| C. CCA | C | **C** ❌ | 不匹配 |
| D. 以上所有 | — | — | ❌ 只有 A 成立 |

- **A ✅** “B”被 `_` 匹配，“A”被 `A` 匹配，`%` 在此匹配空串 → 命中。
- **B ❌** 第 2 字符是 I，不是 A。
- **C ❌** 第 2 字符是 C，不是 A。
- **D ❌** 若选 D，则 B、C 也必须命中，但它们不命中。

**知识点**：§3.4.1 通配符。**`_` 是“占一个字符”，`%` 是“占零个或多个字符”**——第 3 题就是在这上面失分，两题应连着练。

### 第14题　“输出无重复的记录” ⚠️ 平台答案错误

**题干**：查询时，若要输出无重复的记录，SELECT 子句中使用的保留字是（ ）。
**选项**：A. **DISTINCT**　B. ALL　C. TOP N　D. TOP N PERCENT
**标准答案：A**（⚠️ 平台判分为 **D**）

- **A ✅** 去重保留字**只有** `DISTINCT`：`SELECT DISTINCT 列… FROM …`。这是 SQL 标准（ANSI/ISO）唯一与“无重复”相关的关键字。
- **B ❌** `ALL` 恰是**相反**：`SELECT ALL`（默认行为）保留全部行，**包括重复**。
- **C ❌** `TOP N` 是 SQL Server 的**方言**，含义是“取查询结果的前 N 行”，**与去重毫无关系**，也不属于标准 SQL。
- **D ❌（平台判为正确，实为错误）** `TOP N PERCENT` 表示“**取结果的前 N% 的行**”（如 `TOP 10 PERCENT`），同样是行数限制，**不删除重复行**。

> ⚠️ **平台判分与标准冲突（本题丢 2.8 分）**
> - **标准答案：A（DISTINCT）**。教材 §3.4.1 明确：“若查询结果中有重复行，可用 `DISTINCT` 去掉重复元组”。
> - **平台答案：D（TOP N PERCENT）**——`TOP` 是 SQL Server 扩展，用途是“取前 N 行/前 N%”，与去重无关，属题库错误。
> - **对比记忆**：`DISTINCT` = 去重；`TOP N` / `TOP N PERCENT` = 限量；`GROUP BY` = 分组。

### 第15题　自然连接的关键词 ✅

**题干**：在 SQL 语句中，自然连接使用的关键词是（ ）。
**选项**：A. **NATURAL JOIN**　B. OUTER JOIN　C. INNER JOIN　D. ROSS JOIN
**标准答案：A**

- **A ✅** `NATURAL JOIN`：**自动**按两表**同名属性（公共属性）**做等值连接，并在结果中**去掉重复的公共列**。
- **B ❌** `OUTER JOIN` 是**外连接**（左外/右外/全外），会**保留不匹配的元组并补 NULL**。
- **C ❌** `INNER JOIN` 是**内连接**（含等值连接、θ 连接），需要**显式写 `ON` 条件**，且**保留重复列**——它不自动去掉同名列。
- **D ❌** `ROSS JOIN` 是 `CROSS JOIN` 的**漏字错拼**（笛卡儿积），错拼本身就说明它不可能是正确答案。

**知识点**：§2.4.2 / §3.4.3。**对比**：

| 连接 | 条件 | 重复列 | 不匹配元组 |
|---|---|---|---|
| 等值连接（INNER，ON 写 `=`） | 显式 ON | **保留** | 丢弃 |
| **自然连接（NATURAL）** | 同名属性自动 | **去掉** | 丢弃 |
| 外连接（LEFT/RIGHT/FULL OUTER） | 显式 ON | 按写法 | **保留并补 NULL** |
| 交叉连接（CROSS JOIN） | 无 | 全保留 | —（= 笛卡儿积） |

### 第16题　自身连接必须定义别名 ✅

**题干**：在 SQL 语句中，自身连接必须要定义表的（ ）。
**选项**：A. 主键　B. **别名**　C. 外键　D. 连接属性
**标准答案：B**

- **A ❌** 主键与连接语法无关。

- **C ❌** 外键与连接语法无关。
- **D ❌** “连接属性”是连接条件的属性，不是必须“定义”的东西。

### 第17题　不满足连接条件的元组也输出 ⚠️ 平台答案错误

**题干**：在 SQL 语句中，若不满足连接条件的元组也作为结果输出，则必须的连接方式为（ ）。
**选项**：A. NATURAL JOING（拼写错）　B. **OUTER JOIN**　C. INNER JOIN　D. ROSS JOIN（拼写错）
**标准答案：B**（⚠️ 平台判分为 **C**）

- **A ❌** `NATURAL JOIN` 是**内连接**的一种特例，只输出匹配元组；“JOING”还是拼写错误。
- **B ✅** **外连接（OUTER JOIN）**的定义就是：**除满足连接条件的元组外，还把不满足条件的“悬浮元组”保留在结果中，另一侧属性填 NULL**。分三种：
  - `LEFT OUTER JOIN`（左外）：保留**左表**全部元组；
  - `RIGHT OUTER JOIN`（右外）：保留**右表**全部元组；
  - `FULL OUTER JOIN`（全外）：两侧都保留。
- **C ❌（平台判为正确，实为错误）** `INNER JOIN` 只输出**两个表能匹配上的行**，不匹配的直接丢弃——这恰好与题干要求**相反**。
- **D ❌** `ROSS JOIN` 拼写错误（应为 `CROSS JOIN`），且交叉连接不做条件匹配，谈不上“不满足条件”。

> ⚠️ **平台判分与标准冲突（本题丢 2.9 分）**
> - **标准答案：B（OUTER JOIN）**。教材 §2.4.2 原文：“**外连接**：如果把悬浮元组（不满足连接条件的元组）也保留在结果关系中，则称为外连接。”
> - **平台答案：C（INNER JOIN）**——与“保留不满足条件的元组”定义直接矛盾，属题库错误。
> - **一句话记**：**“保留不匹配的 → 外连接（OUTER）；只留匹配的 → 内连接（INNER）”**。

### 第18题　`>ANY` 的等价写法 ✅

**题干**：在不相关子查询中，`>ANY` 谓词与使用（ ）组函数的 SELECT 子查询可以等价转换。
**选项**：A. **>MIN**　B. >=MIN　C. >MAX　D. >=MAX
**标准答案：A**

**核心逻辑**：`X > ANY (子查询集合)` 表示“X **大于集合中的某一个**”，只要 X 比**最小的那个大**即可成立：

```
X > ANY S  ⟺  X > MIN(S)
```

- **A ✅** `>MIN` 完全等价。举例：S = {60, 70, 90}，X = 65：65 > 60 成立（有元素比它小）→ 存在；而 65 > MIN(S)=60 也成立。两者同真假。
- **B ❌** `>=MIN` 不等价：若 X 恰好等于最小值（如 X=60），`X > ANY` 为**假**（没有严格小于它的元素），而 `X >= MIN` 为**真**，出现分歧。
- **C ❌** `>MAX` 对应的是 **`>ALL`**（大于**所有**元素 ⟺ 大于最大值），张冠李戴。
- **D ❌** `>=MAX` 对应的是 **`>=ALL`**。

**四组等价必须背熟**（不相关子查询中，`ANY`=`SOME`）：

| 谓词 | 等价聚集函数 | 记忆 |
|---|---|---|
| `> ANY` | `> MIN` | 大于“某一个”→ 打败最弱者即可 |
| `>= ANY` | `>= MIN` | 不小于最小者 |
| `< ANY` | `< MAX` | 小于“某一个”→ 比最强者小就行 |
| `<= ANY` | `<= MAX` | 不大于最大者 |
| `> ALL` | `> MAX` | 大于“所有”→ 必须打败最强者 |
| `>= ALL` | `>= MAX` | 不小于最大者 |
| `< ALL` | `< MIN` | 小于“所有”→ 必须小于最弱者 |
| `<= ALL` | `<= MIN` | 不大于最小者 |
| `<> ALL` / `!= ALL` | 等价 `NOT IN` | — |
| `= ANY` | 等价 `IN` | — |

**知识点**：§3.4.5 嵌套查询（ANY/ALL 谓词）。

### 第19题　并集并去重的集合操作 ✅

**题干**：将两个 SELECT 各自的结果集并为**一个**集，并**删除重复元组**的集合操作是（ ）。
**选项**：A. **UNION**　B. UNION AL　C. INTERSECT　D. MINUS
**标准答案：A**

- **A ✅** `UNION`：**并集 + 自动去掉重复元组**（`UNION` 的结果默认按集合语义处理）。

### 第20题　001 号课成绩高于 002 号课 ✅

**题干**：有关系表 SC(S#, C#, Score)，求“001”号课成绩比“002”号课成绩高的所有学生的学号。
**选项**：
A. Select S1.S# From SC S1, SC S2 Where S1.S# = S2.S# and S1.C#='001' and S2.C#='002' ;
B. **Select S1.S# From SC S1, SC S2 Where S1.S# = S2.S# and S1.C#='001' and S2.C#='002' and S1.Score > S2.Score;**
C. Select S1.S# From SC S1, SC S2 Where S1.S# = S2.S# and S1.C#='001' and S2.C#='002' and S2.Score > S1.Score;
D. Select * From SC S1, SC S2 Where S1.S# = S2.S# and S1.C#='001' and S2.C#='002' and S1.Score > S2.Score;
**标准答案：B**

三个必要条件（缺一不可）：
1. `S1.S# = S2.S#`：**同一学生**的两条选课记录（自身连接）；
2. `S1.C#='001' and S2.C#='002'`：S1 是 001 号课，S2 是 002 号课；
3. `S1.Score > S2.Score`：**001 的成绩 > 002 的成绩**（方向的正确性）。

- **A ❌** 缺第 3 个条件。它会输出“**同时选了 001 和 002** 的所有学生”，不比较成绩高低。
- **B ✅** 三个条件齐全，方向正确，且 SELECT 只投影 `S1.S#`（题目只要学号）。
- **C ❌** 条件方向**写反了**：`S2.Score > S1.Score` 求的是“002 高于 001”的学生。
- **D ❌** 虽然条件对，但 `SELECT *` 输出两表拼接后的**全部列**（S#、C#、Score、S#、C#、Score），题目只要**学号**，投影错误。

**知识点**：§3.4.3 自身连接、§3.4.1 投影。**这题同时考了“连接条件 + 方向 + 投影”三件事**，是 SQL 题型的典型综合体。
**等价的其他写法**（可对照理解）：
```sql
SELECT S1.S#
FROM   SC S1 JOIN SC S2 ON S1.S# = S2.S#
WHERE  S1.C#='001' AND S2.C#='002' AND S1.Score > S2.Score;
```

### 第26题　ALTER TABLE 属于哪类功能 ✅

**题干**：SQL 集数据查询、数据操纵、数据定义和数据控制功能于一体，语句 `ALTER TABLE` 实现哪类功能？
**选项**：A. 数据查询　B. 数据操纵　C. **数据定义**　D. 数据控制
**标准答案：C**

- **A ❌** 查询是 `SELECT`。
- **B ❌** 数据操纵是 `INSERT/UPDATE/DELETE`（对**数据**动手）。
- **C ✅** `ALTER TABLE` 改的是**表的结构（模式）**，属于 **DDL（数据定义语言）**。同族：`CREATE/ALTER/DROP`。
- **D ❌** 数据控制是 `GRANT/REVOKE`（权限、并发、恢复）。

**知识点**：§3.1、§3.3。此题为作业1 第26题的重复考点。

### 第27题　哪个不是数据操纵语句 ✅

**题干**：下列 SQL 语句中，（ ）不是数据操纵语句。
**选项**：A. INSERT　B. **CREATE**　C. DELETE　D. UPDATE
**标准答案：B**

- **A ❌（是 DML）** `INSERT` 插入数据。
- **B ✅（不是 DML）** `CREATE` 是 **DDL**，建立表/视图/索引等**结构**。
- **C ❌（是 DML）** `DELETE` 删除数据。
- **D ❌（是 DML）** `UPDATE` 修改数据。

**知识点**：§3.1。**DML 三件套：INSERT / UPDATE / DELETE（＋查询 SELECT）**。

### 第28题　授予权限 ✅

**题干**：SQL 使用（ ）语句为用户授予系统权限或对象权限。
**选项**：A. SELECT　B. CREATE　C. **GRANT**　D. REVOKE
**标准答案：C**

- **A ❌** `SELECT` 是查询，是**被授予**的权限对象（如 `GRANT SELECT ON 表 TO 用户`），本身不是授权语句。
- **B ❌** `CREATE` 是 DDL 语句，同样是被授予的系统权限之一。
- **C ✅** `GRANT 权限 ON 对象 TO 用户 [WITH GRANT OPTION];` —— **授予**。系统权限（如 `CREATE TABLE`）与对象权限（如 `SELECT/UPDATE ON 表`）都用它。
- **D ❌** `REVOKE` 是**收回**权限，方向相反。

**知识点**：§3.1、§4.2 授权（GRANT/REVOKE）。**一授一收**：`GRANT` 给，`REVOKE` 收。

### 第29题　涉及空值的错误操作 ✅

**题干**：SQL 中，下列涉及空值的操作，不正确的是（ ）。
**选项**：A. AGE IS NULL　B. AGE IS NOT NULL　C. **AGE = NULL**　D. NOT (AGE IS NULL)
**标准答案：C**

- **A ✅（正确）** 判断为空，合法。
- **B ✅（正确）** 判断非空，合法。
- **C ❌（不正确，即答案）** 空值**不能用 `=` 比较**：`AGE = NULL` 的结果是 **UNKNOWN**（三值逻辑），永远筛不出任何行，应写成 `AGE IS NULL`。
- **D ✅（正确）** `NOT (AGE IS NULL)` 等价于 `AGE IS NOT NULL`，合法。

**知识点**：§3.6 空值的处理。**三值逻辑**：TRUE / FALSE / **UNKNOWN**；NULL 参与的任何比较（`= <> < >`）和算术都返回 UNKNOWN，只有 `IS [NOT] NULL` 能判定空值。

### 第30题　哪一行能插入表 S ✅

**题干**：`CREATE TABLE S (SNo CHAR(6) NOT NULL, SName CHAR(8) NOT NULL, SEX CHAR(2), AGE INTEGER);`
**选项**：
A. ('991001', '李明芳', 女, '23')
B. **('990746', '张为', NULL, NULL)**
C. (NULL, '陈道一', '男', 32)
D. ('992345', NULL, '女', 25)
**标准答案：B**

- **A ❌** 两处错：① `女` **未加单引号**（字符串常量必须加引号）；② `'23'` 是字符串赋给 INTEGER 列（虽有 DBMS 会隐式转换，但本身不规范，且第①处已致错）。
- **B ✅** SNo='990746'（非空、6 字符 ✓）、SName='张为'（非空 ✓）、SEX 为 NULL（**该列未声明 NOT NULL，允许空** ✓）、AGE 为 NULL（允许空 ✓）。全部合法。
- **C ❌** SNo 为 NULL，**违反 `SNo NOT NULL`**（且它是主码候选，违反实体完整性）。
- **D ❌** SName 为 NULL，**违反 `SName NOT NULL`**。

**知识点**：§3.5.1、§3.3 约束、§3.6 空值。与第 2 题**完全同型**（都是考“NOT NULL 的列不能插空，其余列可为空”）——两题连做，说明这是必考套路。

### 第31题　查“数据库”课的男生姓名 ✅

**题干**：S(SNo,SName,Sex,Age)、C(CNo,CName,Teacher)、SC(SNo,CNo,Grade)，查选修“数据库”课程的“男”学生姓名。
**选项**：A. S　B. SC,C　C. S,SC　D. **S,C,SC**
**标准答案：D**

| 需要的信息 | 所在表 |
|---|---|
| 姓名、性别 | **S** |
| 课程名 = “数据库” | **C** |
| 谁选了这门课 | **SC** |

- **A ❌** 只有 S，不知道谁选了“数据库”。
- **B ❌** 缺 S，**拿不到姓名和性别**。
- **C ❌** 缺 C，**不知道哪门课叫“数据库”**（除非硬编码 CNo，不是通用解）。
- **D ✅** 三表连接：`S.SNo = SC.SNo AND SC.CNo = C.CNo AND C.CName = '数据库' AND S.Sex = '男'`。

**知识点**：§3.4.3 多表连接。与第 9 题**同一模板**（只是表名、属性名换了）——这说明“**要的字段跨几个表，就得连几个表**”。

### 第32题　修改表结构的命令 ✅

**题干**：在 SQL 中，修改数据表结构应使用的命令是（ ）。
**选项**：A. **ALTER**　B. CREATE　C. CHANGE　D. DELETE
**标准答案：A**

- **A ✅** `ALTER`（配合 `TABLE`）修改表结构：`ALTER TABLE 表 ADD/DROP/MODIFY …`。
- **B ❌** `CREATE` 是**新建**，不是修改。
- **C ❌** `CHANGE` 不是独立命令（MySQL 中它是 `ALTER TABLE` 的子句）。
- **D ❌** `DELETE` 删除**数据**，不动结构。

### 第33题　打印学生成绩单该做什么运算 ✅

**题干**：学生(学号,姓名,性别,班级)、课程(课程名称,学时,性质)、成绩(课程名称,学号,分数)。打印成绩单，含**学号、姓名、课程名称、分数**，应对这些关系进行（ ）。
**选项**：A. 并　B. 交　C. 乘积　D. **连接**
**标准答案：D**

先把“列从哪来”摊开：

| 输出列 | 来自 |
|---|---|
| 学号 | 学生、成绩（都有，公共属性） |
| 姓名 | **学生** |
| 课程名称 | 课程、成绩（都有，公共属性） |
| 分数 | **成绩** |

- **A ❌** 并（∪）要求两关系**同构**（列数、类型相同），这三张表结构不同，不能并。
- **B ❌** 交（∩）同样要求同构，且语义不符。
- **C ❌** 乘积（笛卡儿积 ×）只是**盲目拼接**，会产生大量无意义的组合（每个学生配每门课），**不筛出“这个学生选的那门课”**。
- **D ✅** **连接（⋈）**按公共属性（学号、课程名称）把三张表“对上号”：`学生 ⋈ 成绩` 得到学生的姓名与分数，再 `⋈ 课程` 得到课程信息（学时、性质等），正是成绩单。

**知识点**：§3.4.3 多表连接、§2.4.2 连接运算。**“并/交要同构，乘积不对号，要对号入座必须连接”**。

### 第34题　层次模型不能表示什么 ✅

**题干**：层次模型不能直接表示（ ）。
**选项**：A. 一对一联系　B. 一对多联系　C. **多对多联系**　D. 一对多和一对一联系
**标准答案：C**

- **A ❌（能）** 1:1 可表示。
- **B ❌（能）** 1:n 正是层次模型（树）的天然场景：一个双亲多个子女。
- **C ✅** 层次模型是**树**：除根外**每个结点有且仅有一个双亲**，而 **m:n 要求“多双亲”**，树结构无法直接表达，只能靠**冗余结点**或**引入中间结点（拆成两个 1:n）**变通。
- **D ❌** 这两类恰恰都能表示。

**知识点**：§1.2.3 常用数据模型（与作业1 第25题、作业2 无重复）。**层次模型的硬伤 = m:n**。

### 第35题　FROM 多个表时系统做什么 ✅

**题干**：当 FROM 子句中出现多个基本表或视图时，系统将执行（ ）操作。
**选项**：A. 并　B. 等值连接　C. 自然连接　D. **笛卡儿积**
**标准答案：D**

- **A ❌** 并（∪）要求两表同构，且不是 FROM 的语义。
- **B ❌** **等值连接需要 `WHERE`/`ON` 给出“相等”条件**；没有条件时不会自动等值连接。
- **C ❌** 自然连接需要**同名属性自动匹配**，FROM 本身不做这件事（`NATURAL JOIN` 才做）。
- **D ✅** `FROM R, S` 在**没有任何连接条件**时，系统先把两张表做**笛卡儿积**（|R|×|S| 个元组、n+m 列），再由 `WHERE` 做选择/连接。所以：**FROM 多表 = 笛卡儿积；WHERE 里的等值条件把它“筛成”连接**。

**知识点**：§3.4.3、§2.4.2。这也解释了第 14 题（作业2）的“笛卡儿积最费时”：**连接写漏条件 → 结果爆炸**，是初学者最常见的性能事故。

本次 88.7 分，共丢 11.3 分，来自 4 道题：

| 题号 | 平台判分 | SQL 标准正解 | 性质 | 失分 |

| **3** | B | B | ✅ **一致**（真正要纠正的是“`_` 的个数”这个知识点：`张____` 是 4 个下划线，匹配 5 个字） | 2.8 |
| **12** | **B（DELETE TABLE S）** | **A（DROP TABLE）** | ❌ 题库错误：`DELETE TABLE` 不是合法 SQL | 2.8 |
| **14** | **D（TOP N PERCENT）** | **A（DISTINCT）** | ❌ 题库错误：`TOP` 是限行，与去重无关 | 2.8 |
| **17** | **C（INNER JOIN）** | **B（OUTER JOIN）** | ❌ 题库错误：内连接只留匹配行，与题干相反 | 2.9 |

**申诉/自证要点（可直接抄给老师）**

1. **第12题**：教材 §3.3.2 “删除基本表”语法为 `DROP TABLE <表名> [RESTRICT|CASCADE];`。SQL 中不存在 `DELETE TABLE` 语句；`DELETE` 的语法是 `DELETE FROM 表名 [WHERE 条件]`，删的是**行**而非表。
2. **第14题**：教材 §3.4.1：“若查询结果中有重复行，可用 `DISTINCT` 去掉重复元组”。`TOP N` / `TOP N PERCENT` 是 SQL Server 的**行数限制**扩展，与“去重”无逻辑关系；且它们不属于标准 SQL。
3. **第17题**：教材 §2.4.2：“若把**悬浮元组（不满足连接条件的元组）也保留**在结果关系中，则称为**外连接**”。`INNER JOIN`（内连接）定义上**只输出满足条件的元组**，与题干要求正好相反。

## 四、考点归纳（第3章 SQL 脉络）

### 4.1 SQL 的组成（第21、26、27、28 题）

| 类别 | 全称 | 语句 | 作用对象 |
|---|---|---|---|
| **DDL** | 数据定义 | `CREATE / ALTER / DROP` | 模式（表、视图、索引） |
| **DML** | 数据操纵 | `INSERT / UPDATE / DELETE / SELECT` | 数据（行/列值） |
| **DCL** | 数据控制 | `GRANT / REVOKE` + 事务控制 | 权限、并发、恢复 |

> 口诀：**定义管“架子”，操纵管“内容”，控制管“权限”。**

### 4.2 表的三大动作（第10、11、12、22、32 题）

| 目的 | 语句 | 备注 |
|---|---|---|
| 建表 | `CREATE TABLE 表(列 类型 约束, …)` | 列级/表级约束 |
| 改表结构 | `ALTER TABLE 表 ADD [COLUMN] 列 类型`<br>`ALTER TABLE 表 DROP [COLUMN] 列 [CASCADE\|RESTRICT]`<br>`ALTER TABLE 表 ADD CONSTRAINT …` | 加列、删列、改类型、加删约束 |
| **删整张表** | `DROP TABLE 表 [CASCADE\|RESTRICT]` | **注意不是 DELETE** |
| 只删/清行 | `DELETE FROM 表 [WHERE]` / `TRUNCATE TABLE` | 表结构保留 |

### 4.3 查询五子句与执行顺序（第1、4、5、6、7、25 题）

```
SELECT [DISTINCT] 列清单      ← 投影（π），DISTINCT 去重
FROM   表/视图 [WHERE]        ← 笛卡儿积/连接
WHERE  条件                   ← 选择（σ），不能含聚集函数
GROUP BY 列                   ← 分组
HAVING 条件                   ← 分组的筛选（可含聚集函数）
ORDER BY 列 [ASC|DESC];       ← 排序（默认 ASC！）
```

**书写顺序**：SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY
**执行顺序**：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY

### 4.4 LIKE 通配符（第3、13 题 + 第4题D项）

| 符号 | 含义 | 例 |
|---|---|---|
| `%` | 任意长度（**含 0 个**）字符 | `'张%'` → 张、张三、张某某 |
| `_` | **恰好 1 个**字符 | `'张_'` → 张三；`'张__'` → 张某某 |
| `[ ]` | 指定范围内 1 个字符（SQL Server 扩展） | `'[张王]%'` |
| `\%`、`\_` | 转义，匹配 `%`、`_` 本身 | `LIKE '%\%%' ESCAPE '\'` |

> **考试必查**：数清楚下划线个数！`张某某` = 3 字 = `'张__'`（2 个下划线），不是 1 个也不是 4 个。

### 4.5 三种连接 + 交叉连接（第15、16、17、35 题）

| 连接 | 关键字 | 条件 | 保留不匹配元组 | 重复列 |
|---|---|---|---|---|
| 等值/θ | `INNER JOIN … ON` | 显式 | ❌ | 保留 |
| **自然** | `NATURAL JOIN` | 同名属性自动 | ❌ | **去掉** |
| **外** | `LEFT/RIGHT/FULL OUTER JOIN` | 显式 `ON` | ✅ **补 NULL** | 按写法 |
| 交叉 | `CROSS JOIN`，或 `FROM R, S` | 无 | — | 全保留（= 笛卡儿积） |

> 自身连接：`FROM 表 A, 表 B`（**必须起别名**，否则无法区分）。

### 4.6 谓词与子查询（第18、19、20 题）

| 写法 | 含义 | 等价 |
|---|---|---|
| `= ANY` | 等于其中某一个 | `IN` |
| `> ANY` | 大于某一个（打败最弱者） | **`> MIN`** |
| `> ALL` | 大于所有（打败最强者） | `> MAX` |
| `< ANY` / `< ALL` | — | `< MAX` / `< MIN` |
| `<> ALL` | 与所有都不同 | `NOT IN` |
| `UNION` / `INTERSECT` / `EXCEPT` | 并（去重）/ 交 / 差 | Oracle 差用 `MINUS` |

### 4.7 空值三原则（第2、8、29、30 题）

1. `NULL` **不是 0、不是空串**，表示“未知/无值”；
2. 判断只能用 **`IS NULL` / `IS NOT NULL`**，用 `= NULL` 永远筛不出行（结果 UNKNOWN）；
3. `NOT NULL` 的列**不能插空值**；**未声明 NOT NULL** 的列可插 NULL。**主码列隐含 NOT NULL。**

### 4.8 视图（第24 题）

| 说法 | 对错 | 说明 |
|---|---|---|
| 视图是外模式 | ✅ | 三级模式中外模式层 |
| 视图是虚表 | ✅ | 只存定义，不存数据 |
| 视图加快**编写** | ✅ | 封装复杂查询 |
| 视图加快**执行** | ❌ | 展开成基表查询，可能更慢（物化视图除外） |

### 4.9 SQL 与关系代数对照（全卷主线）

| 关系代数 | SQL | 题号 |

| 投影 π | `SELECT 列`（**SQL 默认不去重**） | 1、25、14 |
