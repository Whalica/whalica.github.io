## 二、逐题解析

### 第1题　“8 个数字组成的字符串”属于哪种完整性 ✅

**题干**：在学生关系中，规定学号的值域是由 8 个数字组成的字符串，其规则属于（ ）。
**选项**：A. 实体完整性约束　B. 参照完整性约束　C. 用户自定义完整性约束　D. 键完整性约束
**标准答案：C**

- **A ❌** 实体完整性约束的是：**主码（主属性）不能取空值**，且主码取值唯一。它只管“非空”，不管“必须是 8 位数字”。
- **B ❌** 参照完整性约束的是**外码**：外码的取值必须是被参照关系中某个元组的主码值，或取空值。与“8 位数字”无关。
- **C ✅** **用户定义的完整性**（也叫域完整性/语义完整性）是**针对具体应用的数据语义要求**写的约束条件，如“学号必须是 8 位数字串”“性别只能是男/女”“年龄在 15–45 之间”。SQL 中用 `CHECK`、`NOT NULL`、`DEFAULT` 等表达。
- **D ❌** 关系模型中**没有“键完整性约束”**这个标准术语（属杜撰项）；标准的三类是实体完整性、参照完整性、用户定义完整性。

**知识点**：§2.3 关系的完整性；§5 数据库完整性（`CHECK` 的实现）。
**延伸**：这题可与作业1 第32题（关系性质）联动记——值域（域）是关系模型的基石，“取哪个域”由用户定义，所以“值域规定”属于用户定义完整性。

### 第2题　关系与关系之间的联系靠什么实现 ✅

**题干**：在关系数据库中，关系与关系之间的联系是通过（ ）实现的。
**选项**：A. 实体完整性　B. 参照完整性　C. 用户自定义完整性　D. 域完整性
**标准答案：B**

- **A ❌** 实体完整性管**一个关系内部**主码非空唯一，管不到“关系之间”。
- **B ✅** **参照完整性 = 外码约束**：关系 R 的外码引用关系 S 的主码，**R 与 S 的联系就是靠这个外码“参照”建立并维持的**。外码要么为空，要么等于被参照表中真实存在的主码值——这就保证了“不引用不存在的实体”。
- **C ❌** 用户自定义完整性针对**具体语义**（如年龄范围），与关系间联系无关。
- **D ❌** 域完整性是“列的取值范围”，也不是关系间的联系（且它是用户定义完整性的组成部分）。

**知识点**：§2.3.2 参照完整性。E-R 图里的联系 → 关系模式后，**要么独立成表，要么以“外码”形式落到某个表里**，这是“联系”在关系模型中的落地方式。

### 第3题　外码的定义 ⚠️ 定义对，但“取值”常被漏考

**题干**：某关系 R 的外键是指（ ）。
**选项**：A. 其它关系的候选键，可以是 R 中的主属性或非主属性　B. 该关系除主键之外的另一个候选键　C. 其它关系的候选键，同时作为 R 的主属性　D. 其它关系的候选键，同时作为 R 的非主属性
**标准答案：A**

- **A ✅** 外码的完整定义：设 F 是关系 R 的一个或一组属性，**但不是 R 的码**；如果 F 与关系 S 的**主码 Ks** 相对应（同域），则称 **F 是 R 的外码**，R 为参照关系，S 为被参照关系。
  - 关键点：外码**本身不要求是 R 的码**，所以它在 R 中**既可能是主属性，也可能是非主属性**——这就是 A 比 C、D 都对的理由。
- **B ❌** 那是**候选码**（R 内部能唯一标识元组的另一组属性），不是外码。这是“把外码和候选码搞混”的典型干扰项。
- **C ❌** 只说“是主属性”，**漏掉了非主属性**的情形，范围太窄。反例：SC(SNo,CNo,Grade) 中 SNo 是主属性（主码的一部分）；而“系主任”若把系主任工号放在系表里，则可能是非主属性。
- **D ❌** 同理，只说“是非主属性”，也漏了主属性情形。

> ⚠️ **需注意（本题的隐藏考点）**：A 只回答了“外码**是**什么”，没回答“外码**取值**是什么”。完整规则是：
> **外码的值要么取空值（NULL），要么等于被参照关系 S 中某个元组的主码值。**
> 如果外码是 R 主码的组成部分，则**不能取空值**（否则违反实体完整性）。这两条经常单独出题。

**知识点**：§2.1.3 码（候选码、主码、外码）、§2.3.2 参照完整性。

### 第4题　关系代数的基础 ✅

**题干**：关系代数运算是以（ ）为基础的运算。
**选项**：A. 关系运算　B. 谓词运算　C. 集合运算　D. 代数运算
**标准答案：C**

- **A ❌** 循环定义——“关系运算以关系运算为基础”等于没说。
- **B ❌** **谓词运算（关系演算）**是关系运算的**另一种表达方式**（元组演算、域演算），与关系代数**并列**而非其基础（§2.5）。
- **C ✅** 关系是**元组的集合**，关系代数的一切运算都建立在**集合运算**之上：并、差、交、笛卡儿积都是集合运算，选择、投影、连接、除也要用集合的观点定义（如“投影后要去掉重复元组”）。
- **D ❌** “代数运算”太笼统（泛泛的抽象代数），不如“集合运算”准确。

**知识点**：§2.4 关系代数概述、§2.2 关系操作。

### 第5题　关系数据库的概念模型 ✅

**题干**：关系数据库的概念模型是（ ）。
**选项**：A. 关系模型的集合　B. 关系模式的集合　C. 关系子模式的集合　D. 存储模式的集合
**标准答案：B**

- **A ❌** “关系模型”是**数据模型的种类**（一代模型），不是一个个具体库的结构，谈不上“集合”。
- **B ✅** 一个关系数据库的**概念模型（逻辑模型）**就是它包含的**全部关系模式的集合**，即“数据库模式 = {R1, R2, …, Rn}”，每个 Ri 是关系模式（表头定义）。
- **C ❌** 子模式（外模式）的集合是**外模式层**，属于局部视图，不是概念模型。
- **D ❌** 存储模式（内模式）是**物理层**，连“概念”都不是。

**知识点**：§2.1 关系模式与关系数据库；对照作业1 的“三级模式”：**模式层 = 关系模式的集合，外模式层 = 视图（子模式）的集合，内模式层 = 存储模式**。

### 第6题　“专门的关系运算” ⚠️ 官方选项漏了“除”

**题干**：关系数据库管理系统能实现的专门关系运算包括（ ）。
**选项**：A. 排序、索引、统计　B. 选取、投影、连接　C. 关联、更新、排序　D. 显示、打印、制表
**标准答案：B**

- **A ❌** 排序、索引、统计是**物理存储/实现层面**的技术（索引是存储结构，排序是算法），**不是关系代数运算**。这是最经典的干扰项。
- **B ✅（官方答案）** **专门的关系运算**指：**选择（选取 σ）、投影（π）、连接（⋈）、除（÷）**四种。B 覆盖了前三种。
- **C ❌** “更新”属于**数据操纵（DML）**而非关系运算；“关联”是通俗说法；排序不是关系运算。
- **D ❌** 显示、打印、制表是**应用层输出**，与运算无关。

> ⚠️ **需注意**：严格说“专门的关系运算”应包含**除（÷）**，B 项少了它。但四个选项里只有 B 是运算（另外三个全是实现层/应用层的东西），**按最佳选择选 B**。若出多选题或填空题，务必写全：**选择、投影、连接、除**（有的教材把“连接”细分为等值连接、自然连接、外连接、半连接）。
>
> 补充对比：**基本关系运算**只有 5 种——**并、差、笛卡儿积、选择、投影**；交、连接、除都可以由这 5 种导出（故称“**导出运算**”）。

**知识点**：§2.2 关系操作、§2.4 关系代数。

### 第7题　先 σ 后 π 的顺序不能反 ✅

**题干**：设学生档案关系模式 S(SNo, SN, Sex, Age)。“从学生档案数据库中检索学生年龄大于 20 岁的学生的姓名”的关系代数式是（ ）。
**选项**：
A. σ_SN(Π_Age>20(S))
B. Π_SN(σ_Age>20(S))
C. Π_SN(Π_Age>20(S))
D. σ_SN(σ_Age>20(S))
**标准答案：B**

- **A ❌** **σ（选择）的下标必须是条件表达式**（对元组求真假），而 `SN` 是一个**属性名**、是投影的对象，不是条件。把 σ 和 π 的功能互换了，**语法错误**。
- **B ✅** 正确顺序：**先按条件选出元组（σ_Age>20），再取所需属性（Π_SN）**。语义为“年龄>20 的学生的姓名”。这也符合**查询优化**的“先选择、后投影”原则（第9章），因为先做选择能大幅减少数据量。
- **C ❌** 内层 `Π_Age>20(S)` 把**条件写进了投影**，投影的下标只能是**属性列名**，不能是条件表达式，**语法错误**。
- **D ❌** σ 的下标同样不能是属性名 `SN`，且连做两次选择得不到“姓名”这一列，**语法＋语义双错**。

**记忆口诀**：**σ 看行（选元组）、π 看列（选属性）**；**σ 的下标是条件，π 的下标是属性名**。

**知识点**：§2.4.1 选择与投影。此题的本质是“σ 与 π 到底谁管行谁管列”。

### 第8题　一个关系只有一个主码 ✅

**题干**：一个关系只有一个（ ）。
**选项**：A. 超码　B. 外码　C. 候选码　D. 主码
**标准答案：D**

- **A ❌** **超码（超键）可以有很多个**：任何能唯一标识元组的属性组都是超码，候选码本身也是超码，再加属性仍是超码 → 数量爆炸。
- **B ❌** **外码可以有多个**：一个表可以同时引用多张表（如成绩表同时引用学生表、课程表）。
- **C ❌** **候选码可以有多个**：如学生表里“学号”和“身份证号”都能唯一标识学生，二者都是候选码。
- **D ✅** **主码是从所有候选码中“选定”的那一个**，所以**一个关系只能有一个主码**（但主码可以是**复合主码**，由多个属性组合而成，这不算“多个主码”）。

**知识点**：§2.1.3 码。层次关系记：**超码 ⊇ 候选码 ⊇ 主码（只留一个）**；外码另属一类，可多个。

### 第9题　关系键的定义 ✅

**题干**：在关系模型中，以下有关关系键的描述正确的是（ ）。
**选项**：A. 可以由任意多个属性组成　B. 至多由一个属性组成　C. 由一个或多个属性组成，其值能唯一标识关系中的一个元组　D. 以上都不对
**标准答案：C**

- **A ❌** “任意多个”不准确：键之所以为键，必须满足**唯一性**和**最小性（无冗余属性）**；“任意”组合起来未必能唯一标识元组（如 {姓名, 年龄} 不一定唯一）。
- **B ❌** 只能一个属性是**错的**，关系键完全可以是**复合键**（如 (学号, 课程号)）。
- **C ✅** 这是标准定义：**由一个或多个属性构成、其值能唯一标识一个元组**的属性组。（严格定义还要加“**且不含多余属性**”，即最小性。）
- **D ❌** C 已正确。

**知识点**：§2.1.3。注意题干说“关系键”是泛称，包含超键/候选键；考试中通常指**候选键**。

### 第10题　任意两元组不能相同 ✅

**题干**：同一个关系模型的任两个元组值（ ）。
**选项**：A. 不能完全相同　B. 可以完全相同　C. 必须完全相同　D. 以上都不对
**标准答案：A**

- **A ✅** 关系是**元组的集合**，集合中**不允许重复元素**，所以任意两个元组至少有一个分量不同。这也是“关系中必须存在候选码”的直观依据。
- **B ❌** 若能完全相同，就无法用码区分、也无法做集合运算。
- **C ❌** 全部相同等于关系里只有一种元组，显然荒谬。
- **D ❌** A 正确。

**知识点**：§2.1.2 关系的性质（第 2 条）、§2.1 关系的数学定义（笛卡儿积的子集）。
**联动**：这正是 SQL 中 `DISTINCT` 存在的原因——物理存储可能因插入重复而产生重复行，`DISTINCT` 把结果“还原”为严格的集合（作业3 第5、14题考的就是它）。

### 第11题　记录顺序可任意颠倒 ✅

**题干**：一个关系数据库文件中的各条记录（ ）。
**选项**：A. 前后顺序不能任意颠倒，一定要按照输入的顺序排列　B. 前后顺序可以任意颠倒，不影响库中的数据关系　C. 前后顺序可以任意颠倒，但排列顺序不同，统计处理的结果就可能不同　D. 前后顺序不能任意颠倒，一定要按照关键字段值的顺序排列
**标准答案：B**

- **A ❌** “必须按输入顺序”是**文件系统**的思维方式；关系中**元组的次序无关紧要**。
- **B ✅** 关系是集合，**行的顺序可以任意交换**，这不改变关系本身，也不改变任何查询结果（除非显式 `ORDER BY` 输出排序）。
- **C ❌** 半对半错：前半句对，但“**统计处理结果可能不同**”是错的——`COUNT/SUM/AVG` 等统计与物理顺序无关（除非用了 `TOP N` 之类依赖顺序的非标准写法，那是 SQL 输出顺序问题，不是关系本身的性质）。
- **D ❌** “必须按关键字段排序”是加了索引/聚簇后的**物理存储**考虑，不是关系的逻辑性质。

**知识点**：§2.1.2 关系的性质第 4 条“行的次序可以任意交换”。

### 第12题　属性不可再分 ✅

**题干**：关系模式的任何属性（ ）。
**选项**：A. 不可再分　B. 可再分　C. 命名在关系模式中可以不唯一　D. 以上都不对
**标准答案：A**

- **A ✅** **属性的原子性**：每个分量必须是**不可再分的数据项**（第一范式 1NF 的要求）。例如“地址”若再拆成“省/市/街道”，就违反了 1NF。
- **B ❌** 允许再分就退化成**非规范化关系（嵌套表）**，关系模型不允许（元组演算/关系代数都建立在原子值之上）。
- **C ❌** **同一关系模式中属性名必须唯一**（不能有重名列），否则无法用属性名引用。（不同关系之间当然可以重名，如两表都有 SNo。）
- **D ❌** A 正确。

**知识点**：§2.1.2 关系的性质第 1 条；§6.2 1NF。**联动**：作业1 第32题问“关系模型性质中错误的描述”，答案 C“列可重名”错，与此题同源。

### 第13题　R−(R−S) = R∩S ✅

**题干**：设有关系 R 和 S，关系代数表达式 R−(R−S) 表示的是（ ）。
**选项**：A. R∩S　B. R∪S　C. R−S　D. R×S
**标准答案：A**

**证明（用集合恒等式）**：
```
R − (R − S)
= R ∩ ¬(R ∩ ¬S)          （差集定义 A−B = A∩¬B）
= R ∩ (¬R ∪ S)            （德摩根律）
= (R ∩ ¬R) ∪ (R ∩ S)      （分配律）
= ∅ ∪ (R ∩ S)
= R ∩ S
```
- **A ✅** 结果就是 R∩S。直观理解：**先把 R 中“不属于 S 的部分”从 R 里挖掉，剩下的自然是 R 与 S 的公共部分**。
- **B ❌** R∪S 需要额外把 S 独有的元素并进来。
- **C ❌** R−S 恰好是“被挖掉的那块”，不是结果。
- **D ❌** 笛卡儿积会改变目数和元组数，与差运算无关。

**知识点**：§2.4.1 集合运算（并、差、交）。**交可以用差来表示**：R∩S = R−(R−S) = S−(S−R)，这是“5 种基本运算导出交”的依据。

### 第14题　最费时的关系运算 ⚠️ “除”是干扰项

**题干**：关系运算中花费时间可能最长的是（ ）。
**选项**：A. 选取　B. 投影　C. 除　D. 笛卡儿积
**标准答案：D**

- **A ❌** 选择（σ）只需**逐行扫描比较**，代价与元组数成正比，是最省的运算之一。
- **B ❌** 投影（π）只做列裁剪＋去重，代价也小（去重可用排序/哈希优化）。
- **C ❌** 除（÷）**逻辑上较复杂**（要用投影、笛卡儿积、差组合实现），单独看也很贵，但它通常是“对已做选择/投影后的小关系”运算，**且很多 DBMS 并不直接提供 ÷ 的物理算法**。
- **D ✅** **笛卡儿积（×）**：结果元组数为 **|R|×|S|**，属性数为 **n+m**，即**两个关系的规模“相乘”**，数据量爆炸式增长，是关系代数中**代价最高**的运算。这也是查询优化中要**极力避免**“先做笛卡儿积再做选择”的根本原因（第9章：**把选择、投影尽量下推，避免大表笛卡儿积**）。

> ⚠️ **需注意**：“花费时间可能最长”考的是**数量级**。理论上任何运算的代价都取决于数据规模与实现，但教材口径一致认为**笛卡儿积的膨胀最严重**。若考试允许讨论，可以补一句：“除运算的内部实现也往往通过笛卡儿积完成，因此二者都贵；而笛卡儿积是名副其实的‘规模相乘’。”**按 D 选**。

**知识点**：§2.1.1 笛卡儿积的基数、§2.4 / 第9章 查询优化。

### 第15题　不成立的集合恒等式 ✅

**题干**：设有关系模式 R 和 S，下列各关系代数表达式不正确的是（ ）。
**选项**：
A. R−S = R−(R∩S)
B. R = (R−S) ∪ (R∩S)
C. R∩S = S−(S−R)
D. R∩S = S−(R−S)
**标准答案：D**

逐条验证：

| 选项 | 恒等式 | 是否正确 | 验证 |
|---|---|---|---|
| A | R−S = R−(R∩S) | ✅ 正确 | 从 R 中去掉 R∩S（即 R 中属于 S 的部分），剩下的正是 R−S |
| B | R = (R−S) ∪ (R∩S) | ✅ 正确 | 把 R 拆成“S 之外的部分”与“与 S 公共的部分”，正好拼回 R |
| C | R∩S = S−(S−R) | ✅ 正确 | 从 S 中去掉 S 中不属于 R 的部分，剩下就是公共部分 |
| **D** | **R∩S = S−(R−S)** | ❌ **错误** | 因为 S−(R−S) **= S**（见下），结果与原式无关 |

**D 为什么错（关键推导）**：对任意 x∈S，`x ∈ R−S` 要求 x∈R 且 x∉S，而 x∈S 使后半句为假，故 `x ∉ R−S` 恒成立。于是 S 中**每个元素都被保留**：
```
S − (R − S) = S        （只要 S 非空）
```
显然 **S ≠ R∩S**。反例：R={1}, S={2}，则 R−S={1}，S−(R−S)={2}，而 R∩S=∅。**D 错。**

> 注意：**C 与 D 只差一个左括号的位置**，这是命题人故意的“形近陷阱”。记法：**“被减的是‘不属于对方’的部分”**——要得到交集，必须挖掉“属于自己但不属于对方”的那块。
> 又：R−(R−S)=R∩S 与 S−(S−R)=S∩R 是**对称的一对**（第13题 + 本题C），而 **S−(R−S) 不对称，必然出错**。

**知识点**：§2.4.1 集合运算及其恒等式。

### 第16题　候选码的定义 ✅

**题干**：在关系模型中，一个候选键是（ ）。
**选项**：A. 必须由多个任意属性组成　B. 至多由一个属性组成　C. 可由一个或多个其值能唯一标识元组的属性组成　D. 以上都不是
**标准答案：C**

- **A ❌** 强制“必须多个”错，**单属性也能当候选码**（如学号）。
- **B ❌** 强制“至多一个”错，**复合候选码合法**（如 (学号, 课程号)）。
- **C ✅** 候选码：**能唯一标识一个元组、且不含多余属性（最小性）** 的属性组，可以是单属性，也可以是多属性。
- **D ❌** C 已正确。

**知识点**：§2.1.3。注意与第9题的区别：第9题问“关系键（泛称）”，本题问“候选键”，两者定义基本重合，只是**候选键必须满足最小性**，而超键不要求。

### 第17题　“选择”的定义 ✅

**题干**：在关系代数的专门关系运算中，从关系中选出满足条件的元组的操作是（ ）。
**选项**：A. 选择　B. 投影　C. 连接　D. 除
**标准答案：A**

- **A ✅** **选择（选取，σ）**：按**条件**对**元组（行）**做筛选，结果关系的**目数（列数）不变**，元组数减少。
- **B ❌** **投影（π）**：按**属性（列）**做筛选，结果是**列减少**（同时去重复元组）。
- **C ❌** **连接（⋈）**：把**两个**关系按条件拼接成更宽的关系。
- **D ❌** **除（÷）**：用于处理“**对所有/全部**”这类查询（如“选修了全部课程的学生”），不是单纯选行。

**知识点**：§2.4.1。“选择管行、投影管列、连接管两个表、除管‘全部’”。

### 第18题　自然连接的前提条件 ⚠️ 严格说是“公共属性”

**题干**：进行自然连接的两个关系必须有（ ）。
**选项**：A. 相同的属性个数　B. 相同的属性　C. 相同的元组　D. 相同的主键
**标准答案：B**

- **A ❌** 属性个数不必相同；自然连接只要求**有公共属性**。
- **B ✅** **自然连接（⋈）**：两个关系中**同名的属性（公共属性）**相等时拼接，并在结果中**去掉重复的公共属性列**。所以前提是“**必须有公共属性**”。
- **C ❌** 元组完全相同就该做并/交，不需要连接；连接正是因为两表“互补”。
- **D ❌** 主键相同完全没必要（事实上两表主键同名的场景很少，且同名不代表同义）。

> ⚠️ **需注意（口径）**：严格讲，**若两关系没有公共属性，自然连接退化为笛卡儿积**（有些教材直接说“自然连接必须在公共属性上做”，即必须有公共属性，否则无意义）。考试按“**必须有相同的属性（公共属性）**”选 B。
> 另外要区分：**等值连接（θ 连接）** 不要求同名属性（可用 `R.A = S.B`），且**保留重复列**；**自然连接**是特殊的等值连接，**去掉重复列**。这是 §2.4.2 的核心对比。

**知识点**：§2.4.2 连接（等值连接、自然连接、外连接、半连接）。

### 第19题　笛卡儿积的规模 ✅

**题干**：关系 R 中有 4 个属性和 3 个元组，关系 S 中有 3 个属性和 5 个元组，则 R×S 的属性个数和元组个数分别是（ ）。
**选项**：A. 7 和 8　B. 7 和 15　C. 12 和 8　D. 12 和 15
**标准答案：B**

**公式（§2.1.1）**：
- 属性数（目）：**n + m = 4 + 3 = 7**
- 元组数（基数）：**|R| × |S| = 3 × 5 = 15**

- **A ❌** 属性对（7），元组错（3+5=8 是“加”，不是笛卡儿积）。
- **B ✅** 7 和 15。
- **C ❌** 属性错（4×3=12 是犯了“乘属性”的错误），元组错（8 是相加）。
- **D ❌** 属性错（12），元组对（15）。

**记忆**：**笛卡儿积对“属性做加法、对元组做乘法”**——4+3=7 目，3×5=15 元组。

**知识点**：§2.1.1 笛卡儿积的定义与基数；此题的“元组相乘”正是第14题“笛卡儿积最费时”的量化依据。

### 第20题　关系的性质（错的一项） ⚠️ 措辞有坑

**题干**：以下关于关系性质的说法中，错误的是（ ）。
**选项**：
A. 关系中任意两个元组的值不能完全相同
B. 关系中任意两个属性的值不能完全相同
C. 关系中任意两个元组可以交换顺序
D. 关系中任意两个属性可以交换顺序
**标准答案：B**

- **A ✅（对）** 关系是元组的集合，**元组不能重复**（同第10题）。
- **B ❌（错，即答案）** **两个属性的“值”完全可以完全相同**！例如学生表里如果有一列“出生年份”和另一列“入学年份”，取值可能整列一样，这**不违反任何规则**。关系模型真正禁止的是 **属性名重名**（同关系内属性名必须唯一），**不是属性取值相同**。
- **C ✅（对）** 元组（行）顺序可任意交换。
- **D ✅（对）** 属性（列）顺序可任意交换（列的位置无关，靠属性名引用）。

> ⚠️ **需注意**：本题的坑在于 **B 把“属性名不能重名”偷换成了“属性值不能相同”**。
> - **属性名**：同一关系内**必须唯一**（不能重名）；
> - **属性值**：**允许**整列重复，甚至两列取值完全一致（如“年龄”和“工龄”都为 30 的情形）。
> 所以 B 错在“值”这个字上；若写“任意两个属性的名字不能完全相同”，那就成了正确的说法，不能选。答简答题时务必写清“**属性名不能重名，属性值可以相同**”。

**知识点**：§2.1.2 关系的性质（5 条）：① 分量原子（不可再分）；② 元组不重复；③ 行序无关；④ 列序无关；⑤ 属性名唯一（同关系内）。

### 第21题　投影后的元组个数 ✅

**题干**：在关系代数中，对一个关系做投影操作后，新关系的元组个数（ ）原来关系的元组个数。
**选项**：A. 小于　B. 大于　C. 等于　D. 小于或等于
**标准答案：D**

- **A ❌** 只在“**投影产生了重复元组**”时才小于；若投影保留了能区分所有元组的属性（如保留了主码），则个数不变。所以不能说“一定小于”。
- **B ❌** 投影只会**减少或保持**元组数，绝不会增加。
- **C ❌** 只在“投影后没有产生重复”时等于。
- **D ✅** 两种情况都可能，故为“**小于或等于**”：投影后要**消除重复元组**（因为关系是集合，不允许重复），因此元组数 **≤** 原有元组数。

**举例**：S(SNo, SN, Sex, Age) 有 3 个元组。
- `Π_SNo(S)` → 3 个元组（学号唯一，**等于**）；
- `Π_Sex(S)` → 若 2 男 1 女，则只剩 2 个元组（**小于**）。

**知识点**：§2.4.1 投影。这也是**投影 ≠ SQL 的 SELECT 列裁剪**的原因：SQL 的 `SELECT 列` **默认不去重**（要写 `DISTINCT` 才等价于关系代数的投影）——这正是作业3 第5、14、25 题的考点。

## 四、考点归纳（第2章脉络）

### 4.1 三类完整性（第1、2 题）

| 完整性 | 约束对象 | 规则 | SQL 实现 |
|---|---|---|---|
| **实体完整性** | **主码** | 主码**非空且唯一** | `PRIMARY KEY` |
| **参照完整性** | **外码** | 外码取空，或等于被参照关系的某个主码值 | `FOREIGN KEY … REFERENCES` |
| **用户定义的完整性** | 具体属性/元组语义 | 值域、取值范围、格式等（如“8 位数字”“性别∈{男,女}”） | `CHECK`、`NOT NULL`、`DEFAULT`、触发器 |

> 口诀：**实体管“主码不空”、参照管“外码不乱”、用户管“业务规则”**。

### 4.2 码的层次（第3、8、9、16 题）

```
超码（能唯一标识的一切属性组，可很多个）
  └─ 候选码（最小超码，可多个）
       └─ 主码（从候选码中选定的那一个，只能 1 个）
外码（引用其他关系主码的属性组，可多个，且可为空）
```

- **候选码必须最小**；**主码唯一但可以是复合主码**；
- **外码 ≠ 候选码**（第3题 B 项的陷阱）。

### 4.3 关系的 5 条性质（第10、11、12、20 题）

① **分量原子性**（不可再分，1NF）
② **元组不重复**
③ **行序无关**
④ **列序无关**
⑤ **属性名唯一**

> 高频陷阱：**“属性值可相同，属性名不可重名”**（第20题）。

### 4.4 关系代数运算全景（第4、6、7、13、14、15、17、18、19、21 题）

```
关系代数
├─ 基本运算（5 种）
│   ├─ 并  R ∪ S
│   ├─ 差  R − S
│   ├─ 笛卡儿积 R × S      ← 目 n+m，元组 |R|×|S|，最贵
│   ├─ 选择 σ（行，条件）
│   └─ 投影 π（列，属性名，去重）
├─ 导出运算
│   ├─ 交  R ∩ S = R − (R − S) = S − (S − R)     ← 第13、15题
│   └─ 连接 ⋈（等值/自然/外/半）与 除 ÷
```

**必背恒等式**（第13、15 题来源）：

| 恒等式 | 说明 |
|---|---|
| R ∩ S = R − (R − S) | 交的差表示（正确对称） |
| R ∩ S = S − (S − R) | 同上，对称形式（正确） |
| R − S = R − (R ∩ S) | 正确 |
| R = (R − S) ∪ (R ∩ S) | 正确（拆分） |
| **S − (R − S) = S** | ❌ 不是交集（本题 D 的陷阱） |

### 4.5 σ 与 π 的分工（第7、17、21 题）

| 运算 | 管什么 | 下标写什么 | 结果规模 |
|---|---|---|---|
| **σ 选择** | 行（元组） | **条件表达式**（如 `Age>20`） | 列数不变，行数减少 |
| **π 投影** | 列（属性） | **属性名列表** | 行数 ≤ 原行数（去重），列数减少 |

> 一句话：**σ 看行看条件，π 看列看属性名；先 σ 后 π 是优化本能**。

### 4.6 与后续作业的直接衔接

- 第21题的“投影要去重” → 作业3 的 `DISTINCT`、`SELECT` 与投影的区别；
- 第6、7题的“专门运算” → SQL 的 `WHERE`（σ）、`SELECT 列`（π）、`JOIN`（⋈）；
- 第8、16、20题的“码与性质” → 第6章 关系数据理论（函数依赖、范式、候选码求解）；
- 第14、19题的“笛卡儿积” → 第9章 查询优化（选择下推、避免笛卡儿积）。
